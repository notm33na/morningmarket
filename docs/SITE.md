# MarketMorning site: signup, unsubscribe, chart proxy

Built in the site folder (`ms-manager-cloudflare/`, a sibling of this repo; a Cloudflare Worker with static assets, deployed with Wrangler, see its README). Referenced from [ARCHITECTURE.md](ARCHITECTURE.md) §4.

## Worker endpoints (`/api/mm/*`, Cloudflare Worker `ms-manager-site`, `nodejs_compat`, `worker-mailer`; Sheet via the Apps Script web app `tools/site-sheet-api.gs`, no Google Cloud)
Secrets: `MM_SCRIPT_URL`, `MM_SCRIPT_SECRET`, `MM_HMAC_SECRET`, `GMAIL_USER`, `GMAIL_APP_PASSWORD`; var `SITE_URL` (`https://www.mediaandsoftwaremanager.com`). Apps Script property `MM_HMAC_SECRET` = the Worker's. Caps come from Config. All writes are stored as plain text (number format `@`), so input never becomes a formula. No logging of request bodies or emails. Static assets: `/mm/coingecko-logo.png` (from the CoinGecko Brand Kit), `/mm/chart-unavailable.png`.

**Token** = `b64url(JSON{h,a,n,x}) + "." + b64url(HMAC_SHA256(MM_HMAC_SECRET, part1))`: `h` = first 32 hex of HMAC(secret, lowercased email) (also TxLog `email_hash`), `a` = `confirm`|`unsub`, `n` = row `token_nonce`, `x` = expiry (confirm 72 h, unsub 24 h). The Worker verifies the signature with `timingSafeEqual`, matching `a` and `x` > now; the Apps Script op then finds the row with matching `n` and `h` and rotates the nonce.

**Sheet access**: one Apps Script op per site action (`subscribe`, `confirm`, `unsubRequest`, `unsubConfirm`), each run under `LockService` and idempotent: the Worker fixes `nonce`, `at` and `newNonce` once, so a retry with the same inputs rewrites the same row, finds its own TxLog row (`[at, type, hash]`) instead of adding another, or sees `newNonce` already on the row and returns the earlier result. The Worker follows Apps Script's redirect by hand (POST → 302 → `script.googleusercontent.com` echo) and retries up to 3 attempts / 60 s when Google loses the result (echo bounces back to `/exec` → "Script function not found: doGet"), answers 5xx, or the lock is busy. Max 2 subrequests per attempt.

**Email budget** (rolling 24 h from TxLog): confirm ≤ 70, unsub_confirm ≤ 30 (separate pools); per `email_hash` ≤ 1 per 15 min and ≤ 3 per 24 h. The op reserves the TxLog row **before** the email is sent (so a failed send still counts). Over budget → email silently skipped, same response. The email is the only work after the response (`ctx.waitUntil`, 30 s).

| Endpoint | Request | Behaviour | Response |
|---|---|---|---|
| POST /api/mm/subscribe | JSON `{email, consent:true, website:""}` | Honeypot filled → no-op. Validate: trim, lowercase, ≤ 254, syntax, first char not `= + - @`, MX lookup (DNS-over-HTTPS, 3 s). Op `subscribe`: new → `pending`; `pending`/`unsubscribed` → `pending` + new nonce; `active`/`waitlist` → nothing. If pending and in budget: TxLog row reserved, confirm sent via `waitUntil` (after the response). | 200 `{ok:true, message:"Check your inbox to confirm."}` for every valid input (incl. honeypot, budget hit, SMTP failure); 400 `{ok:false, error:"invalid_email"\|"consent_required"}`; 500 `{ok:false, error:"server_error"}` (Sheet unreachable after retries) |
| GET /api/mm/confirm?t= | token | Read-only page with a "Confirm subscription" POST button (link scanners don't press it). | HTML |
| POST /api/mm/confirm | form `t` | Verify `a=confirm`. Op `confirm`: active < cap → `active`, else `waitlist`; set `confirmed_at`. | 303 → `/?mm=confirmed\|waitlisted\|expired\|invalid\|error#marketmorning` |
| GET /unsubscribe | – | Static page: email form + honeypot. | HTML |
| POST /api/mm/unsubscribe | JSON `{email, website:""}` | Op `unsubRequest`: if pending/active/waitlist and in budget, TxLog row reserved; link (`a=unsub`) sent via `waitUntil`. | Always 200 `{ok:true, message:"If that address is subscribed, we've emailed a confirmation link."}`; 400 bad syntax |
| GET /api/mm/unsubscribe/confirm?t= | token | Read-only page with "Unsubscribe" POST button. | HTML |
| POST /api/mm/unsubscribe/confirm | form `t` | Verify `a=unsub`. Op `unsubConfirm`: set `unsubscribed`, `unsubscribed_at`; promote oldest `waitlist` (by confirmed_at) if below cap, in the same locked run. | 303 → `/?mm=unsubscribed\|expired\|invalid\|error#marketmorning` |
| GET /api/mm/chart?l=&v= | `l` = `[A-Z]{2,5}` comma list (≤ 10), `v` = same count of `-?\d{1,4}\.\d{2}` | Exactly these 2 params in this order and valid → build bar config (green ≥ 0, red < 0) and POST to `https://quickchart.io/chart` (552×300 png, white). Anything else → 302 to static `/mm/chart-unavailable.png` (no render, cached 1 day). QuickChart error → same redirect, `s-maxage=300`. | `image/png`, `Cache-Control: public, max-age=31536000, s-maxage=31536000, immutable` |

Routing (the Worker runs first for every request): apex `mediaandsoftwaremanager.com` → 301 to `https://www.mediaandsoftwaremanager.com` (same path and query); clean URLs (`/x.html` and `/index` → 308, `/x` and `/x/` serve `x.html`); `/mm/*` → `Cache-Control: public, max-age=86400`; `/api/mm/(subscribe|confirm|unsubscribe)*` → `Cache-Control: no-store`; anything else → 404.

Rate limit: Workers rate-limit binding `MM_RATE_LIMITER` on `/api/mm/` except `/api/mm/chart`, 10 req / 60 s per IP → 429 (approximate, counted per Cloudflare location). Waitlist: promotion only on unsubscribe; when the owner raises the cap they flip `waitlist` rows by hand. Confirms run under the script lock, so the cap is never exceeded; Feed `active_count` = MIN(count, cap).

Form privacy note: "We store your email, signup/confirmation times and status in a private Google Sheet, processed by Google, Make and Cloudflare only to send one email each weekday. It is never sold, never sent to AI or analytics tools, and unsubscribed or unconfirmed addresses are deleted monthly. Unsubscribe from any email; questions: reply to any digest."
